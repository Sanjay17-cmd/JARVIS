SECTION 1: SYSTEM ARCHITECTURE & ENGINEERING OVERVIEW
--------------------------------------------------------------------------------

JARVIS is a modular Windows desktop AI companion featuring a transparent, borderless,
floating robot on the desktop, interactive chest buttons, system tray controls,
expandable state machine, event bus, SQLite scheduling (reminders, alarms, wellness, tasks),
focus/pomodoro mode, floating toast notifications, and AI provider integration.

Key Architectural Pillars:
1. Transparent Floating Overlay (jarvis/ui/overlay.py):
   - Frameless, always-on-top window using flags:
     Qt.WindowStaysOnTopHint | Qt.FramelessWindowHint | Qt.Tool | Qt.NoDropShadowWindowHint
   - Translucent background: Qt.WA_TranslucentBackground and Qt.WA_ShowWithoutActivating.
   - Smooth drag-to-move with boundary clamping and multi-monitor safe margins.
   - Autonomous floating motion with sine-wave float oscillation and target seeking.
   - Master 33ms single-timer loop (Part L optimization) ensuring low CPU usage (<1%).
   - Asynchronous background frame generation via QThread so startup is instant (<100ms).

2. Procedural Robot Art & Rendering (jarvis/assets/robot_painter.py):
   - Procedurally generated using Pillow (PIL) into 32-bit RGBA PNG frames.
   - 7 animation states: IDLE, THINKING, SPEAKING, LISTENING, ERROR, SUCCESS, PAUSED.
   - Dynamic eye glow, visor, antenna sway, mouth amplitude, and chest status LEDs.
   - Caching layer in jarvis/assets/__init__.py avoids re-rendering on subsequent runs.

3. Chest Controls & Color Indicators (Parts B & K):
   - 4 clickable interactive buttons placed on the robot's chest:
     * Button 0: Voice / Mic (Default Cyan idle, Green active/listening, Red muted)
     * Button 1: Vision / Camera (Default Cyan idle, Green active)
     * Button 2: Reminders & Tasks (Amber indicator when reminder due, clears in 10s)
     * Button 3: Quick Action / Settings (Orange accent)
   - Hit testing with hover, pressed, and active visual states.

4. State Machine & Event Bus (jarvis/core/state.py, jarvis/core/event_bus.py):
   - 7 core states with transition guards. Pre-pause state memory.
   - Thread-safe pub/sub event bus decoupling UI from business logic.

5. Command Router (jarvis/core/command_router.py):
   - Dispatches natural language commands, regex patterns, and exact commands:
     * System: help, status, version, pause, resume, reset, settings
     * Reminders: 'remind me in X to Y', 'reminders', 'snooze', 'alarm at HH:MM', 'alarms'
     * Tasks: 'task <title>', 'tasks', 'done <id>'
     * Focus: 'focus 25', 'focus stop', 'focus status'
     * AI fallback: Routes unhandled queries to AI provider.

6. Configuration Architecture (Split Config):
   - Settings Dialog (jarvis/ui/settings_dialog.py): Slim, clean UI with only 8 primary
     settings (Opacity, Robot Size, Always on Top, Panels on Top, Movement, Animations,
     Notifications, Wellness).
   - Advanced Config (jarvis/config/advanced_config.py): Full INI file stored at
     %APPDATA%\JARVIS\advanced_settings.ini containing 20+ fine-grained parameters
     (speeds, intervals, colors, thresholds) with comments and validation limits.
   - Reset Defaults button restores both settings.json and advanced_settings.ini.

7. Scheduling & Database (jarvis/scheduling/):
   - SQLite DB at %APPDATA%\JARVIS\jarvis.db (WAL mode, indexed).
   - reminder_service.py: Reminders & alarms, recurrence (daily, weekly, weekdays), snooze,
     and 30s background tick checking.
   - wellness_service.py: Hydration, stretch, and eye-rest (20-20-20 rule) reminders with
     quiet hours enforcement.
   - task_service.py: SQLite task list CRUD with priority and status transitions.
   - focus_service.py: Pomodoro state machine (IDLE -> FOCUSING -> SHORT_BREAK -> LONG_BREAK).

8. Floating Toast Notifications (jarvis/ui/notification.py):
   - Polished glassmorphism floating toast at bottom-right of screen.
   - Smooth slide-in and fade-out animations, snooze button, priority queue.

9. AI Provider Abstraction (jarvis/ai/provider.py):
   - AIProvider abstract base class.
   - EchoProvider: Local, zero-dependency offline fallback.
   - OpenAIProvider: Connects to GPT models if OPENAI_API_KEY is supplied.

SECTION 3: CRITICAL OPEN ISSUES & USER FEEDBACK (NEXT PRIORITIES)
--------------------------------------------------------------------------------

The following issues and design questions were raised by the user in recent turns:

1. ISSUE: Chest Buttons Overlap & Misalignment with Robot Image
   - Problem: The 4 chest buttons in jarvis/ui/overlay.py do not match the exact drawn
     coordinates of the chest plate in jarvis/assets/robot_painter.py.
   - Root Cause: In robot_painter.py, the robot anatomy is procedurally calculated based on
     canvas dimensions (head_y, chest_y, chest_w, chest_h). However, overlay.py was using
     hardcoded/estimated button hit-rectangles.
   - Scaling Failure: When the user changes the robot size in Settings (e.g., from 200px to
     300px), the buttons drift outside the robot's body or overlap each other because the
     hit-rects were not dynamically derived from the robot painter's exact anchor points.
   - Recommended Solution:
     a) Export a layout manifest or helper function from robot_painter.py:
        get_chest_button_rects(canvas_w, canvas_h) returning exact (x, y, w, h) for each of
        the 4 buttons matching the exact visual chest LEDs.
     b) In overlay.py, bind button positions directly to this helper so any resize
        automatically and flawlessly updates the hit-rects and visual indicator coordinates.
     c) Add calibration offsets to advanced_settings.ini so the user can nudge coordinates.

2. QUESTION: 2D Procedural Pillow Drawing vs 3D Blender Model
   - User Question: "Can I get a Blender 3D drawing itself for this? And also it has no
     animations at all! Having same animations!"
   - Architectural Evaluation:
     * Approach A (Recommended for Performance & Aesthetics): Pre-rendered 3D Sprite Sheets
       from Blender. Render a 3D model in Blender (glTF / FBX with EEVEE/Cycles) into transparent
       PNG sequences across multiple expressive states (idle, talking, nodding, thinking,
       waving, celebratory dance, alert, sleep). Replace robot_painter with a sprite-sheet loader.
       This provides Pixar-quality 3D visuals while keeping Python CPU usage near 0%!
     * Approach B: Real-time 3D Viewport using PySide6 QtQuick3D or PySide6 QWebEngineView + Three.js.
       Requires 3D engine initialization with transparent window flags. Higher memory footprint
       (~150MB+ vs ~35MB currently) but allows real-time camera angles and dynamic lighting.
     * Approach C: Immediate 2D Animation Expansion. Add 6+ new expressive animation routines to
       robot_painter.py: waving arm, head tilt, eye expressions (happy arcs, focused slit,
       surprised wide eyes), floating hover trail, and sound-reactive waveform mouth.

3. PENDING PHASE 2/3 ROADMAP ITEMS:
   - Part C: Voice pipeline (Microphone push-to-talk, Sherpa-ONNX / Whisper local STT, pyttsx3 TTS).
   - Part D: Chat panel streaming text and persistent history in SQLite.
   - Standalone Windows 64-bit EXE build via PyInstaller (JARVIS.spec).
